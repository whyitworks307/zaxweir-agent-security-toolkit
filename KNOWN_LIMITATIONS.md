# Known limitations (read before relying on results)

1. **BUILDER-VERIFIED ONLY.** No independent security QC has accepted this release candidate.
2. **Coordinated rollback is not detected.** Restoring an older audit log together with its matching anchor (and an older nonce ledger) verifies as valid. No rollback protection is claimed against compromise of both the log and its anchor. Durable anti-rollback needs an external monotonic counter or remote witness; not provided. A test documents this gap.
3. **Duplicate action_id tracking is in memory** per `Gate` instance; it does not survive restarts.
4. **Symlink attacks may be SKIPPED** on machines where the standard user cannot create symlinks (WinError 1314). Junction and hard-link attacks still run. Skips are reported, never counted as passes.
5. **Race tests are probabilistic.** A clean race run shows no leak was observed in N iterations, not that none is possible.
6. **Windows reader scope:** local NTFS, regular files up to 1 MiB, single-link files only. Network shares, ReFS specifics, oplocks/filter drivers and Windows versions other than the tested one are not verified.
7. **Enrollment is a trust bootstrap.** If the hashes given to `enroll()` are wrong or attacker-chosen, the reader will faithfully serve that content.
8. **Path policy is lexical** for non-Windows use; it does not consult a filesystem.
9. **Process-wide handle counts** are not used as a pass criterion; per-module open/close balance is checked instead. The intermittent +1 (138 vs 137) seen in the older Repair01 build was reproduced by the builder outside any test harness: about 27-30 s into a Python process, Windows adds a Thread and an Event handle and drops an ALPC Port handle (net +1), with no reader code involved. The exact Windows component is not identified (would need elevated tracing). This attribution is builder-only and awaits independent confirmation.
10. **No arg schemas per tool:** besides type/length and escalation keys, extra arguments are allowed by policy.
11. Not a sandbox, EDR or OS access control. It does not stop an agent that has direct OS access.
12. Owner Apache-2.0 approval, holder/year and private security channel are recorded in rc8. Inherited source/provenance clearance and public-release authorization remain open; see LICENSING_STATUS.md.
13. **Reader provenance:** the builder described the Windows reader as a clean-room rewrite in rc4 (staging CLEANROOM_LOG / PROVENANCE_DECISION). The rewrite was done by the same AI-assisted builder that maintained earlier versions, so separation rests on documented procedure and similarity evidence, not personnel isolation; independent verification is pending. File identity uses the 64-bit file index (ReFS 128-bit IDs not supported).
14. Security reporting uses verified `founder@zaxweir.com`, controlled and checked daily by Christopher Wright. Delivery was confirmed November 5, 2026. No response or repair deadline is promised; public release still requires the remaining gates.

15. **State size limits in the Muse review candidate:** audit logs are limited to 8 MiB and persistent nonce ledgers to 1 MiB. Verification and appends refuse larger state. Before capacity is reached, a trusted operator must archive/rotate state under an integration-specific procedure that preserves replay protection and audit continuity. No automatic deletion, reset or rotation is supplied.
16. **State paths are trusted configuration:** audit, anchor, nonce-ledger, key and report paths and their parent directories must be controlled by the trusted operator. These APIs are not a filesystem containment boundary for caller-selected state paths. Do not place them in agent-writable directories.
17. **Interrupted state requires operator review:** a crash can leave audit or nonce-consumption lock files. Stop all writers and independently verify saved state before an authorized operator removes a stale lock. Never automatically break a lock based on a timeout or PID alone. The package is not power-loss certified.
18. **Gate retries:** every structurally valid first-seen action ID is consumed by that Gate instance even when authorization or auditing fails. A retry requires a new action ID and fresh human approval where applicable. The caller must handle idempotency across restarts; Gate never executes an action itself.
19. **Report pairs are not atomic:** JSON and Markdown reports are created separately with no-overwrite semantics. Interrupted or colliding writes can leave an incomplete pair. Treat a report as complete only after the producing command succeeds and both expected artifacts are present.

20. **rc5 command-search repair:** the junction setup probe now resolves cmd.exe through GetSystemDirectoryW and refuses lookup failure. A harmless invalid cmd.exe in the current directory reproduced selection failure in R1. The repaired candidate is tested separately. This is a specific command-selection fix, not protection against a compromised OS or administrator.
21. **Publication remains blocked:** inherited native-reader provenance, applicable exact-artifact independent acceptance and explicit owner final-hash publication authorization remain outstanding. Owner copyright/license direction and private-channel verification are recorded. The original clean-room log names Vex as an AI-assisted builder; the reviewer must disclose any overlapping role and arrange independent provenance assessment rather than self-certifying that history.
22. **Platform coverage:** CPython 3.12.14/Linux and 3.13.15/Windows were used for builder validation. The declared Python >=3.11 range, ReFS, other filesystems/architectures/OS versions, true power loss and privileged symlink coverage are not independently verified.

23. **Junction probe path syntax:** percent-expansion paths and invalid command-path characters are refused for junction setup. Such setup limits are not verified attack denials. This restriction concerns the CMD-based probe, not a new guarantee for arbitrary native file names.

24. **rc6 native cleanup failure:** explicit close raises on a failed Windows close result and does not count it as success. The pin is invalidated. No automatic retry or process-wide leak attribution is promised; destructor cleanup remains best effort.
25. **rc6 request validation:** identifiers must match completely. No downstream trimming or aliases are authorized by a gate decision. Schema versions must be JSON integers, not booleans or floats.

26. **rc7 root-swap coverage correction:** historical rc6 root_boundary_swap_race records with swaps=0 did not exercise root substitution, despite their pass labels. rc7 records rename failures explicitly and reports zero substitutions as SKIPPED with passed=false. A separate intermediate-directory rename check verifies later old-path reads fail closed when setup succeeds. Races remain bounded observations.

27. **rc8 cleanup repair:** every held path handle is attempted after a cleanup failure. A primary read/security exception is preserved with a cleanup-failure note; cleanup failure after a successful read raises rather than returning bytes. Modeled faults and reported-fault injection after real successful Windows closes are distinguished from actual OS CloseHandle failure. A genuinely failed close may still leave that failed handle open; no automatic retry is promised.
28. **rc8 ancestor substitution:** a deterministic ancestor rename and replacement is attempted without weakening pin sharing. Successful setup and subsequent read outcome are reported separately. This is distinct from the direct-root rename race; blocked setup remains a skip.
29. **Audit reproduction and remaining uncertainty:** rc8 investigation reproduced a log/anchor split and traced FileExistsError to a reused PID-based temporary filename. Fresh exclusive sibling temporaries and owned-file cleanup repair that reproduced class. The creator of the colliding file and the cause of the original rc7 event are not proven. Real I/O failures can still split log/anchor and latch the writer closed; recovery requires trusted operator review. Passing repeats are bounded evidence, not power-loss certification.
